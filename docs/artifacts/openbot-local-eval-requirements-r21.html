OpenBot · Installer requirementsRevision 2 · 20 Oct 2026Runtime proposal · unvalidated

Local installer requirements

A small installer installs all software and dependencies. The user then runs OpenBot, signs in with CopilotKit, selects an AI provider, and completes setup.

Confirmed: standard OS permission prompts and a restart with automatic resume are acceptable. No separate Docker installation, terminal commands, or manual resource settings.

Requirements

  • The installer owns dependency installation, configuration, updates, and recovery.
  • Desktop is the UI. The CLI owns Intelligence, credentials, licensing, and renewal.
  • Installation finishes before CopilotKit sign-in. Bot activation waits for provider validation.
  • macOS and Windows remain in scope. Under 15 minutes remains an unmeasured target.

Proposed change

  • Replace “Docker Desktop required” with an installer-managed runtime.
  • Recommended candidate: Docker Engine in a private Linux VM or WSL distribution.
  • Keep k3d and the hybrid OpenBot stack, subject to full compatibility tests.
  • The runtime choice is a recommendation. It is not an agreed or tested implementation.

Feasibility conclusion

One installer is feasible in principle.

OS consent and restart/resume fit the confirmed requirement. A universal zero-interaction install is not the claim. Hardware and policy restrictions still limit supported machines.

Decision needed

Docker Desktop-only scope must change.

The revised requirement removes a user-installed Docker prerequisite. Option B is proposed for validation. Select the release runtime after evidence from both platforms.

Revised requirements

User corrections supersede the original manual-Docker and manual-resource prerequisites. R01–R12 are presentation references.

RefAreaRequired behavior
R01Dependency installationNo preinstalled Docker, CLI, package manager, or developer tools. Download verified assets automatically. No terminal commands or manual settings.
R02Bootstrap and resumeSmall signed installer, versioned manifest, pinned digests, resumable downloads, progress, retry, and persisted installation checkpoints. Treat installer size separately from total download size.
R03OS setupRequest standard elevation only when needed. Enable supported OS features and resume in the signed-in user context after an approved restart. Detect unsupported hardware or policy blocks early.
R04Runtime ownershipDesktop manages the selected runtime and provides a private Docker endpoint/context to both stacks. No unauthenticated TCP Docker API. Never silently change the user’s default context or overwrite another runtime.
R05ResourcesCheck host capacity and apply required settings automatically. Original estimates: 16 GB host, 8 GiB runtime RAM, 4 CPUs, 50 GiB free disk. 12 GiB runtime RAM recommended. Validate combined peaks and preserve existing global WSL settings.
R06Authentication and licenceRun OpenBot before sign-in. Desktop opens browser authorization and hands a short-lived, one-time code to the CLI via stdin or protected IPC. The CLI owns refresh storage, EULA-backed licence setup, and renewal.
R07CLI contractCLI owns Intelligence topology, lifecycle, licensed readiness, and endpoint JSON. Add support for the selected runtime endpoint/context. The exact contract and Windows support remain to be validated.
R08Provider and chatChoose provider, enter own key, run minimal validation, and store secrets only in OS-backed secure storage. Invalid keys keep setup open. No Bot activation or chat before all prerequisites pass.
R09NetworkingPublish only configured loopback endpoints. Validate host↔guest forwarding, reverse callbacks, supervisor socket access, and volume paths. Loopback in the host and guest are different network namespaces.
R10LifecycleStart runtime → Intelligence readiness → OpenBot. Stop OpenBot → Intelligence → owned runtime when safe. Retain both stacks’ data. Offer separate health/restart actions. Do not stop unrelated workloads.
R11Renewal and diagnosticsWarn from day 25. Explicit renewal and EULA acceptance only. User-reviewed local diagnostics redact credentials, auth codes, chat, provider secrets, and persistent application data.
R12Release evidenceClean-machine macOS/Windows tests cover installation, reboot/resume, sign-in/EULA/licence, provider validation, first chat, interruption/retry, upgrades, retained data, lifecycle, renewal, and redaction.
