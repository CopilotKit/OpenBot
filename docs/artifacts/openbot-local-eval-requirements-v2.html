OpenBot local installer · v2

One installer owns software acquisition, dependencies, runtime configuration, and recovery. Docker Desktop with CLI-managed k3d is the primary path. Podman is a contingency under separate investigation.

Current-code observations are pinned to source. Requirements below describe intended behavior; platform, licensing, security, and clean-machine qualification still require evidence.

Required sequence

Agreed sequence. Installation prepares software; sign-in authorizes and activates the local evaluation.

Download small installer → install everything → run OpenBot → sign in with CopilotKit → choose AI provider → success.

Decisions for implementation

These decisions settle the working design. Release gates below remain explicit.

AreaDecision
First releaseApple silicon macOS and Windows x64. Intel Macs and Windows ARM are deferred until validated. Linux is outside this installer release.
RuntimeDocker Desktop is the primary implementation target. The installer owns its acquisition and settings. No user-installed Docker prerequisite. A retained existing runtime is reused only if supported; unrelated workloads and settings are preserved.
FallbackPodman CLI with an app-managed VM is the first contingency to validate. No Podman Desktop UI is required by this candidate. The separate investigation must prove full-stack support before a default change.
Scope of licence contingencyThe contingency addresses Docker Desktop subscription/embedding terms. It is not a requirement to remove every Docker-named binary, API, or library. Open-source Compose can remain, subject to its own notices.
OwnershipDesktop owns installer/UI, machine prerequisites, runtime configuration and recovery. CLI owns Intelligence topology, credential exchange/refresh, eval licensing/renewal, service lifecycle, readiness and loopback endpoints.
OS setupStandard permission prompts and an approved restart with automatic resume are allowed. No terminal commands, manual dependency installs, or manual resource settings in normal setup or recovery.
Installation boundaryPrepare the app, tools, runtime and distributable cache before sign-in. Provision/start licence-bound services after sign-in and EULA acceptance. Protected payload distribution must be resolved before shipping the exact install-everything promise.
EULA / organizationThe person accepts for the selected organization under the current CLI policy. Do not assume a personal, organization-free grant. Select automatically only when the eligible organization is unambiguous.
Resources / timingInitial design budget: 16 GB host, 8 GiB runtime RAM minimum, 12 GiB recommended, 4 CPUs, 50 GiB free disk. Installer configures supported settings automatically. Under 15 minutes is a test target; resource peaks and total download size are unmeasured.
Expiry / renewalUse CLI-reported licence validity and expiry. Warn within five days of expiry: day 25 for a 30-day grant. Current Enterprise terms can differ. Renewal requires an explicit click and EULA acceptance; never silently renew.
InstallationsOne OpenBot installation per user per computer. The installer chooses its location; normal setup has no folder field. Repair fixes that installation in place. Moving or replacing it is an explicit action that states what happens to existing data. At most one local Intelligence stack is created for it, which is the stack that starts and stops with OpenBot. Hosted and enterprise setup can keep the folder choice.
Data / scopeRetain both stacks’ data and keep the per-user computer migration separate. No distribution gating work, SSO, managed provider keys, or separate local dashboard sign-in.

Lifecycle and recovery

No automatic destructive teardown.

TriggerBehavior
StartVerify runtime → ask CLI to start Intelligence → wait for reported readiness/licence → start OpenBot → gate chat on provider validation.
StopStop OpenBot first, then ask CLI to stop Intelligence. Stop an installer-owned runtime only when safe; never stop unrelated workloads.
FailureShow independent runtime/Intelligence/OpenBot health. Offer targeted Retry, Restart Intelligence, Restart OpenBot, and local diagnostics review.
Provider failureRemain on provider setup, identify provider and failure category, allow key edits or another provider, keep Bot activation/chat blocked.
PortsCLI owns Intelligence endpoints. Desktop retains separate loopback ports for OpenBot. Provide recoverable conflicts without container inspection.
DiagnosticsLocal bundle: installer/Desktop logs, CLI version and structured status, anonymized resource results, port/lifecycle errors. Exclude credentials, auth codes, provider keys, chat and persistent data. Review before sharing.
